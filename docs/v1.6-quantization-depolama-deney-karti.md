# V1.6 — Quantization ve depolama optimizasyonu deney kartı

## Amaç ve sınır

V1.6, yüksek boyutlu dense vektörlerin bellek, disk ve latency maliyetini ölçer.
İlk aday scalar INT8 quantization'dır; original vector rescoring ve oversampling
ile kalite kaybı kontrol edilir. Quantized koleksiyon mevcut dense koleksiyondan
ayrı tutulur.

Qdrant local client quantization ayarını uygulamadığı için bu özellik local
runtime'da fail-closed'dur. Quantization yalnızca Qdrant server üzerinde
etkinleştirilebilir; local-first V1 dense yolu değişmez.

## Deney koşulları

1. Float32 dense baseline.
2. Scalar INT8, `rescore=true`, oversampling `1.0`.
3. Scalar INT8, `rescore=true`, oversampling `2.0`.
4. İhtiyaç oluşursa original vector memory tier ve product/binary quantization.

Her koşul aynı corpus, sorgu seti, filtre ve warm-up politikasında çalıştırılır.
Quantized indeksin arka planda hazır hale gelme süresi ayrıca ölçülür.

## Metrikler ve kabul kapısı

- Exact baseline'a karşı Recall@k, MRR, nDCG ve filtre recall
- p50/p95/p99 latency, throughput ve error rate
- vector/index/payload/snapshot disk boyutu
- RSS/RAM, build/optimizer süresi ve update freshness
- rescore/oversampling maliyeti

Quantization ancak RAM/disk veya latency hedefinde anlamlı kazanım sağlar,
Recall regression bütçesini aşmaz ve restore/rollback güvenilir kalırsa aday
olarak kabul edilir. Küçük corpus ölçümü tek başına genel karar değildir.

## Güvenlik ve rollback

Quantized koleksiyon ayrı manifest ve koleksiyon adı taşır. Snapshot, checksum ve
provenance sözleşmesi baseline ile aynı kalır. Sorunda `VDB_RETRIEVAL_MODE=dense`
ile float32 koleksiyona dönülür; quantized koleksiyon silinmeden inceleme için
korunabilir.

Kaynak: [Qdrant quantization](https://qdrant.tech/documentation/manage-data/quantization/),
[Qdrant storage](https://qdrant.tech/documentation/manage-data/storage/).

## İlk server benchmark sonucu

Docker Qdrant server'da scalar INT8 + original-vector rescore + oversampling
`2.0` ile PromtGen README corpus'undaki 100 sorgu çalıştırıldı:

```text
recall_at_k=1.0000  mrr_at_k=0.9157  ndcg_at_k=0.9378
negative_success_rate=0.0000  error_rate=0.0000
p50=32.282 ms  p95=49.729 ms  p99=64.097 ms
```

Dense baseline'a göre kalite aynı kaldı; iki chunk'lı küçük corpus'ta quantization
latency avantajı göstermedi. Bu nedenle varsayılan dense koleksiyon değişmedi.
RAM/disk tasarrufu ve optimizer süresi, gerçek kapasite corpus'u oluşunca ayrıca
ölçülecek.
