# V1.7 final ölçüm runbook'u

Bu belge geliştirme sırasında çalıştırılmayacak uzun testlerin, gerçek kişisel
corpus ve insan incelemeli fixture hazır olduğunda tek bir sırayla yürütülmesi
içindir. Komutlar privacy-safe artifact üretir; kaynak metni, sorgu metni veya
cevap metni Git'e alınmaz.

## 0. Ön koşullar

- `data/sources/` gerçek kişisel kaynaklarla doldurulmuş olmalı.
- Local embedding modeli cache'lenmiş olmalı veya harici provider kullanımı
  açıkça seçilip veri paylaşımı kararı kaydedilmiş olmalı.
- Fixture en az 300 sorgu, her sorgu türünde en az 30 kayıt, development/
  validation/test split'leri, large belge kovası ve `manual`/`reviewed` label
  provenance'ı taşımalı.
- Aynı corpus checksum'ı, parser sürüm kümesi, chunking sürümü ve embedding
  manifest'i tüm artifact'lerde korunmalı.

İlk hızlı kapı kontrolü runtime başlatmadan yapılabilir:

```powershell
uv run vdb final-readiness `
  --inventory data/derived/corpus-inventory.json `
  --fixture data/benchmarks/representative-personal-queries.json `
  --fixture-manifest data/benchmarks/representative-personal-query-fixture-manifest.json `
  --corpus-manifest data/manifests/corpus-manifest.json `
  --output data/derived/final-readiness.json
```

Bu rapor yalnızca sayıları ve kapı durumlarını taşır. Final koşusunda
`--strict` kullanılır; `overall_status=incomplete` ise ölçüm başlatılmaz.

## 1. Corpus kimliği ve extraction kalitesi

Önce inventory ve manifest yeniden üretilir; eski artifact'ler güncel corpus'a
bağlanmaz:

```powershell
uv run vdb corpus-inventory `
  --root data/sources `
  --output data/derived/corpus-inventory.json `
  --manifest data/manifests/corpus-manifest.json

uv run vdb corpus-quality `
  --inventory data/derived/corpus-inventory.json `
  --output data/derived/corpus-quality-report.json
```

Format bazında `failed_count`, `empty_extraction_count` ve `duplicate_count`
incelenir. PDF/DOCX/HTML extraction sırası ve içerik kaybı gerçek örneklerle
manuel kontrol edilir. Raporun parse elapsed alanları yalnızca hafif bir format
runtime sinyalidir; peak-RAM veya process timeout ölçümü değildir. Bu iki sinyal
gerekiyorsa ayrı worker/process ölçümüyle ayrıca kanıtlanmalıdır.

## 2. Fixture kabul kapısı

Shard'lar collision kontrolüyle birleştirilir, coverage raporu alınır ve final
validator çalıştırılır:

```powershell
uv run vdb fixture-merge queries `
  --input data/benchmarks/shards/queries-*.json `
  --output data/benchmarks/queries-final.json

uv run vdb fixture-merge labels `
  --input data/benchmarks/shards/labels-*.json `
  --output data/benchmarks/labels-final.json

uv run vdb fixture-coverage `
  --fixture data/benchmarks/queries-final.json `
  --manifest data/benchmarks/query-fixture-manifest.json `
  --labels data/benchmarks/labels-final.json `
  --corpus-manifest data/manifests/corpus-manifest.json `
  --output data/benchmarks/results/fixture-coverage.json

uv run vdb fixture-validate `
  --fixture data/benchmarks/queries-final.json `
  --manifest data/benchmarks/query-fixture-manifest.json `
  --labels data/benchmarks/labels-final.json `
  --corpus-manifest data/manifests/corpus-manifest.json
```

`fixture-validate` başarıyla dönmeden retrieval veya cevap kalitesi ölçümü
başlatılmaz. `derived` veya `review-required` label final kabul değildir.

## 3. Dense baseline ve abstention calibration

Önce threshold ve rerank kapalı tek dense baseline koşusu çalıştırılır. Validation
skorları ayrı artifact olarak çıkarılır:

```powershell
uv run vdb benchmark `
  --fixture data/benchmarks/queries-final.json `
  --fixture-manifest data/benchmarks/query-fixture-manifest.json `
  --corpus-manifest data/manifests/corpus-manifest.json `
  --labels data/benchmarks/labels-final.json `
  --repeat 1 `
  --scores-output data/benchmarks/results/abstention-scores-validation.json `
  --scores-split validation `
  --output data/benchmarks/results/dense-baseline.json

uv run vdb abstention-calibrate `
  --fixture data/benchmarks/queries-final.json `
  --scores data/benchmarks/results/abstention-scores-validation.json `
  --split validation `
  --output data/benchmarks/results/abstention-calibration.json
```

Threshold yalnızca validation split'te seçilir. Test split'i threshold seçmek
için kullanılmaz; seçilen değer test koşusunda bir kez doğrulanır. En az bir
pozitif ve bir gerçek negative sorgu yoksa calibration fail-closed reddedilir.

## 4. Uzun süreli concurrency ve kapasite

Local ve server Qdrant koşulları ayrı artifact'ler olarak, cold/warm ayrımı
belirtilerek çalıştırılır. Örnek başlangıç matrisi:

```powershell
uv run vdb concurrency-probe `
  --fixture data/benchmarks/queries-final.json `
  --fixture-manifest data/benchmarks/query-fixture-manifest.json `
  --corpus-manifest data/manifests/corpus-manifest.json `
  --labels data/benchmarks/labels-final.json `
  --concurrency-levels 1 2 4 8 16 `
  --repetitions 20 `
  --warmup-repetitions 3 `
  --output data/benchmarks/results/local-concurrency-warm.json
```

Aynı koşul cold başlangıçta ve `VDB_QDRANT_URL=http://localhost:6333` ile
server Qdrant'ta tekrarlanır. p50/p95/p99, error rate, CPU/RAM, tazelik ve
restore süresi ayrı raporlanır. Toplam istek bounded primitive limitini aşarsa
koşu bölünür; limit artırılarak güvenlik kapısı devre dışı bırakılmaz.

## 5. RAG cevap kalitesi

Retrieval, context ve answer metrikleri ayrı tutulur. İnsan değerlendirmesi
ham cevap/source metni yerine yalnızca privacy-safe artifact'e yazılır:

```powershell
uv run vdb rag-evaluation-summary `
  --input data/benchmarks/rag-evaluations-reviewed.json `
  --output data/benchmarks/results/rag-evaluation-summary.json
```

Özet; relevance, faithfulness, citation correctness ve abstention correctness
oranlarını provenance ile birlikte taşır. Otomatik judge veya citation coverage
tek başına factuality kanıtı sayılmaz.

## 6. Harici provider ve opt-in modlar

Harici embedding aynı fixture/corpus üzerinde dense local baseline'a karşı
ayrı ölçülür: kalite, latency, retry, cache hit/miss ve veri paylaşımı kararı.
Hybrid, rerank, late-interaction ve quantization yalnızca ölçüm sonucu anlamlı
katkı gösterirse rapora eklenir; dense varsayılanı değiştirilmez.

## 7. Docker server smoke ve kapanış

Docker server smoke testleri local Qdrant storage ile aynı klasörü kullanmadan
çalıştırılır. Üç smoke testi başarılı olduktan sonra sonuçlar karar günlüğüne
eklenir. Son olarak final audit'teki tüm açık satırlar gerçek artifact ve
ölçümle kanıtlanmadan goal tamamlandı sayılmaz.

Bu runbook'un uygulanması sırasında üretilen gerçek corpus, label, skor,
cevap değerlendirme ve sonuç dosyaları `private-local` kabul edilir; `.gitignore`
kapsamı dışına çıkarılmaz.
